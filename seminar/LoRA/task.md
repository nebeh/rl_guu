# Лабораторная: два LoRA-адаптера и сравнение стилей

## Цель

Обучить **два LoRA-адаптера** к одной и той же базовой модели и показать, что адаптер меняет стиль генерации, а веса базы остаются на месте.

Корпуса:

1. Даниил Хармс — <https://www.lib.ru/HARMS/harms.txt>
2. Антон Чехов — <https://lib.ru/LITRA/CHEHOW/maska.txt>

И обучение, и генерация идут через Hugging Face: `transformers` и `peft`. Отдельный рантайм не нужен. Адаптер, который сохранил `Trainer`, тем же вызовом `PeftModel.from_pretrained` надевается на базу.

## Что сдать

1. Скрипт подготовки данных и скрипт обучения (или ноутбук).
2. Скрипт генерации: одна база, затем та же база с адаптером Хармса и с адаптером Чехова.
3. Отчёт на 1–2 страницы: гиперпараметры, размер корпусов после чистки, три генерации, короткий разбор отличий.
4. Файл `generations.md` ровно в таком виде (один и тот же промпт, `temperature` одинаковая):

```text
Промпт: Напиши рассказ о ...

### Базовая модель
...

### LoRA: Хармс
...

### LoRA: Чехов
...
```

Промпт придумываете сами. Тема должна быть **нейтральной и бытовой** (например, человек опоздал на трамвай, сосед постучал в дверь, пропала чайная ложка). Не копируйте сюжет из корпуса.

Зафиксируйте в отчёте: имя модели, `temperature`, `max_new_tokens`, seed.

## Ограничения

- Одна и та же базовая модель для обоих адаптеров. Рекомендуется `Qwen/Qwen2.5-1.5B-Instruct`.
- Обучаете только LoRA (или QLoRA). Полные веса базовой модели не меняете и не сохраняете вторую копию базы.
- Оба адаптера обучаете с **одинаковыми** гиперпараметрами. Отличаться должен только корпус.
- В обучение не подмешивайте чужие тексты «для объёма».
- Тексты lib.ru в репозиторий не кладите. В отчёте достаточно ссылки и описания чистки.

## Среда

- Python 3.10+, PyTorch, `transformers`, `peft`, `accelerate`. GPU желателен (хватит 8 ГБ для 1.5B в QLoRA). Без GPU допустим `Qwen2.5-0.5B` и меньше шагов — предупредите об этом в отчёте.

## Ход работы

### 1. Корпус

Страницы lib.ru — это HTML в кодировке **windows-1251**, не UTF-8. Если открыть файл как UTF-8, кириллица развалится, и адаптер выучит мусор.

Сделайте для каждого автора отдельный JSONL. Каждая строка — один объект:

```json
{"text": "<полный рассказ в UTF-8>"}
```

Минимальная чистка:

- декодировать windows-1251;
- выкинуть HTML-теги, навигацию lib.ru, колонтитулы, оглавление и примечания издания;
- разрезать файл на отдельные рассказы, а не склеивать всё в один документ;
- выбросить слишком короткие обрывки (ориентир: меньше ~200 символов);
- не нормализовать стиль: авторская пунктуация и обрывы фраз — часть сигнала, особенно у Хармса.

В отчёте укажите число рассказов и число токенов (или символов) **после** чистки по каждому автору.

### 2. Обучение

Формат примера — тот же chat template, которым вы потом генерируете. Иначе адаптер учится не на том шаблоне, которым вы его спрашиваете.

Пример пользовательской реплики при обучении: «Напиши короткий рассказ.» В ответ — текст рассказа из корпуса. Системный промпт на обучении и на генерации должен совпадать. Можно обойтись без системы, но тогда и при генерации её не добавляйте. Тема в промпте сравнения («Напиши рассказ о …») может быть конкретной: роли и набор служебных токенов при этом те же.

Ориентир гиперпараметров (оба прогона одинаковые):

| Параметр | Значение |
| --- | --- |
| rank `r` | 16 |
| `lora_alpha` | 32 |
| dropout | 0.05 |
| target modules | все attention и MLP проекции (`q/k/v/o`, `gate/up/down`) |
| эпохи | 2–3 |
| effective batch | 8 (например, batch 1 и gradient accumulation 8) |
| learning rate | 2e-4, AdamW |
| max length | 512–1024, что влезает в память |
| квантизация базы | 4-bit QLoRA, если мало VRAM |

Сохраните адаптер в формате PEFT (`adapter_config.json` + `adapter_model.safetensors`), отдельно для Хармса и для Чехова. В конфиге должны быть `r`, `lora_alpha`, `target_modules` и `base_model_name_or_path`. Файл адаптера — десятки мегабайт, не размер полной модели. Слитый в базу checkpoint адаптером не считается.

Следите за train loss. Если loss за первую эпоху не падает вообще, сначала проверьте кодировку и шаблон чата, а не «добавляйте эпохи».

### 3. Генерация с адаптером

Базу загрузите один раз:

```python
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-1.5B-Instruct")
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-1.5B-Instruct", torch_dtype=torch.bfloat16
)
```

Дальше три прогона одной и той же функции генерации. Первый — голая база. Второй и третий — та же база с адаптером:

```python
adapted = PeftModel.from_pretrained(model, "output/harms")
```

После прогона адаптер снимите (`unload`), затем наденьте каталог Чехова. Не загружайте три полные копии весов и не вызывайте `merge_and_unload`, если хотите оставить базу неизменной для следующего адаптера.

Промпт заверните в тот же chat template, что и обучение (`apply_chat_template`, `add_generation_prompt=True`). В диалоге одна реплика `user`. Ответ декодируйте только по новым токенам, без повторного промпта.

Один промпт, три вызова, одни и те же `temperature`, `max_new_tokens` и seed. Меняется только то, надет ли адаптер и какой.

### 4. Сравнение

В разборе ответьте по существу, без общих слов «стиль стал лучше»:

- Чем ответ Хармса отличается от базы: длина фраз, абсурд, обрыв сюжета, повторы, прямая речь.
- Чем ответ Чехова отличается от базы: бытовая деталь, ирония, речь персонажей, концовка.
- Где адаптер **не** сработал: модель пишет как база, смешивает авторов, сыплет обрывками из обучения, теряет русский.

Если оба адаптера неотличимы от базы, это результат эксперимента. Опишите, что проверили (путь к адаптеру, loss, шаблон), а не подгоняйте текст руками.
